# Utility registry audit — Phase 4

Registry source: src/data/freeToolsData.ts (38 entries). Runner routing is in src/components/utilities/UtilityRunner.tsx; heavy groups are lazy-loaded. This is an individual route/implementation inventory. The direct browser sweep loaded all 38 routes without a missing runner, page error, or horizontal overflow. That confirms route wiring and initial UI only; it does not prove every transformation is correct.

The functional browser checks during this audit exercised the JSON formatter with valid JSON and verified formatted output, plus the YouTube and Instagram URL validation workflows. Existing automated tests cover registry completeness, route rendering, QR matrix construction/oversize rejection, latest-request handling, and YouTube/Instagram URL parser positive and negative vectors. Other media transformations, downloads, corrupt/oversized file behavior, and mobile/keyboard paths remain unverified unless called out in the implementation description. No unsupported general-purpose social media downloads are offered.

## Environment-limited paths

- Transcription returns an explicit setup state when provider credentials are absent. This checkout has no OPENAI_API_KEY, Supabase service credentials, or Upstash Redis credentials; production backend behavior was not exercised.
- MP4 to MP3 uses lazy FFmpeg WebAssembly, but an actual media fixture was not run through conversion in this audit.
- YouTube and Instagram utilities validate supported URL shapes and point users to official ownership/export workflows; they do not download media. URL validation is not represented as proof of downloader behavior.
- The image resizer accepts only PNG/JPEG/WebP, caps input at 25 MB, rejects images above 40 megapixels, and caps output at 8,192 px per side / 40 megapixels. A generated 1×1 PNG was loaded, resized, and downloaded; the exported file was inspected with file(1) and confirmed as a 1×1 PNG. Corrupt/oversized fixture behavior remains unverified.
