## GitHub Projects implementation review

- **Records:** 13 verified repository records are public; four held-out records (`Open-Higgsfield-AI`, `Continue`, `n8n`, `WhisperSpeech`) are excluded. Refresh responses only overlay metadata for existing verified records; they do not promote candidates. The research lists are separate source records.
- **Search / filters / sort / pagination:** covered by `tests/github_projects_directory.test.js`; search uses all query terms, categories include secondary memberships, structured filters include license/language/self-hosting/GPU/API-key, and pagination returns nine items per page.
- **Metadata endpoint:** `api/github-projects.js` is GET-only and allowlisted to the 13 verified names. It uses GitHub’s public API without a token, records rate limits, caches in-memory for 15 minutes and CDN responses for five minutes, and returns stale cached data after failed refresh. Concurrent in-flight rejection also follows the stale/error response path.
- **Untrusted data:** README excerpts and repository descriptions are sanitized and length-limited; React renders them as text, with no `dangerouslySetInnerHTML`. External homepage values are restricted to HTTP(S).
- **Classification:** editorial license/category/requirements/notes remain separate from fetched metadata. GitHub metadata cannot automatically change editorial status. Open-Higgsfield-AI remains `license-unclear` and is not allowlisted.
- **SEO and navigation:** `/github-projects` has route title/description and canonical URL handling through the existing app; the page attaches `CollectionPage`/`ItemList` JSON-LD; sitemap contains one route. Browser QA confirmed canonical `https://switchroute.in/github-projects`, a `CollectionPage` item list of 13 records, and the page title. Desktop and mobile render the same grouped links. Browser QA verified the mobile project link, 44px target, Escape close, focus restoration, no horizontal overflow, and no page errors.
- **No secret scan result:** the GitHub metadata client contains no token or client-side credential. The endpoint’s user agent and API request headers contain no credential.
